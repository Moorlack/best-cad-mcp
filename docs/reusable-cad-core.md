# Повторное использование CAD-возможностей

Вторая цель проекта согласована 2026-09-24: новые общие возможности должны
работать вне архитектурного сценария и быть пригодными для будущего плагина.
Первоначальная инженерная цель сохраняется. Это не перенос кода в другой
плагин: его интерфейсы и репозиторий пока не предоставлены.

## Что унифицировано

`analyze_geometry` — общий MCP-инструмент, доступный в core/lean/full.
Он читает результат свежего scan, не меняет и не сохраняет DWG.
Ни названия слоёв, ни названия блоков не назначают объектам архитектурные роли.

Параметры:

- handles: необязательный непустой список точных handles;
- layers: необязательный непустой список точных имён слоёв;
- при обоих фильтрах используется пересечение, без фильтров — весь снимок;
- entity_limit: 1–100000, по умолчанию 10000;
- gap_tolerance: явный положительный допуск в единицах координат;
- reference_lengths: прежний контракт handle/length/units/source (до 20 LINE).

Ответ `geometry-analysis/v1`: выбранные объекты и покрытие, диагностика LINE,
группы контактов, зазоры между ними, проверки полилиний и отношения контуров,
атрибуты блоков, контрольные длины. Отсутствующие/отфильтрованные handles и
слои указаны явно. Неподдерживаемые объекты не исчезают из сведений о покрытии.
Пустая выборка не доказывает отсутствие геометрии в исходном DWG.

Лимиты алгоритмов сохранены: 100 горизонтальных LINE, 100 контуров по 256
вершин, ограниченный бюджет сравнения рёбер. Содержимое блоков/Xrefs,
кривые контуры и произвольная 3D-топология не получили новой поддержки.
`coverage_complete` групп относится только к выбранным LINE; неподдерживаемые
типы перечислены отдельно и не означают, что весь чертёж проверен.
Площади геометрические; вложенность не подтверждает отверстие.
Единицы, заявленные в DWG, не подтверждают фактический масштаб.

## Общая реализация и совместимость

`line_geometry.py` и `line_networks.py` содержат единственную реализацию
диагностики и связных компонент. `wall_lines.py` и `wall_networks.py` стали
адаптерами архитектурного отбора. Старые поля, предупреждения и ID групп
сохранены; новый инструмент не требует переименовать слои в WALL.

Карта остальных наработок:

| Возможность | Повторное использование |
| --- | --- |
| Контуры, вложенность и контакты | Общие boundaries.py / boundary_relations.py; используются обоими отчётами |
| Контрольные длины и преобразование единиц | Общий scale_references.py; используется обоими отчётами |
| Атрибуты блоков | Общий block_attributes.py; сырой текст остаётся данными, не инструкциями |
| INSUNITS и метаданные блоков | Уже общие scan → SQLite → CAD-IR; не зависят от архитектурных имён |
| Изображения и visual self-test | Общие средства сервера; не требуют архитектурного анализа |
| Карточка и история проекта | Существующий отдельный API пригоден для инженерных проектов; схема строительная, произвольной универсальной схемой не объявляется |
| Архитектурная классификация и readiness | Предметный адаптер; не переносятся в общую геометрию |
| Установщик | Доставляет общий MCP из fork; AutoCAD и Revit остаются независимыми |

## Подключение из другого продукта

Первый путь — вызывать `analyze_geometry` через установленный MCP.
Второй — вызвать чистую Python-функцию со снимком CAD-IR v2:

```python
from src.cad_understanding.geometry_analysis import build_geometry_report

report = build_geometry_report(snapshot, layers=["PART-OUTLINE"], gap_tolerance=0.5)
```

Эта точка входа не импортирует AutoCAD, MCP или SQLite и проверена в Python
без site-packages. Она принимает CAD-IR, а не файл DWG: загрузку/преобразование
данных обеспечивает вызывающий продукт. На данный момент код остаётся в fork,
отдельный независимый wheel/SDK не выпускается. При подключении использовать
одну версию ядра, а не создавать расходящиеся копии алгоритмов.

## Проверки и выпуск

187 тестов выбранного набора и линтер PASS; отдельная проверка подтвердила
совпадение старых ответов и ID с версией до рефакторинга. Native MCP проверен
локально на синтетическом CAD-IR, общий Python API — без сторонних пакетов.
Проверки старого установщика clone/Repair/stash/divergence PASS.
Новый CMD и зависимости не требуются.

Живая проверка нового установленного инструмента ожидается после Repair.
Сценарий: четыре LINE на слое PART-OUTLINE без архитектурных токенов, цепочка
A–B, пересечение B–C, отдельная D с зазором 0.25. analyze_geometry с фильтром
слоя должен дать группы A/B/C и D, при допуске 0.5 — связь зазора, без склейки.
Архитектурный инструмент не должен объявлять эти линии стенами.
После анализа повторный scan должен подтвердить неизменность геометрии.
