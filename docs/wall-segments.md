# Пары параллельных линий и кандидаты участков стен

Этот шаг продолжает `wall_networks`: две грани одной стены обычно не касаются
друг друга и поэтому остаются в разных группах контактов. Их связывает только
параллельность и расстояние между ними. Поиск включается явно, заданным
диапазоном расстояний; без параметра ответы прежние.

## Общее ядро: `parallel_line_pairs`

`analyze_geometry(parallel_separation_range=[min, max])` и чистая функция
`build_geometry_report(..., parallel_separation_range=...)` находят пары
горизонтальных LINE выбранного набора, у которых:

- одна горизонтальная плоскость;
- угол между прямыми не больше `parallel_angle_tolerance_degrees`
  (по умолчанию 0.01°, максимум 5°);
- проекции перекрываются на ненулевую длину;
- расстояние между линиями на всём участке перекрытия лежит в [min, max]
  (единицы координат DWG); касание и пересечение не считаются парой.

Для пары возвращаются ID, handles, минимальное/максимальное/среднее расстояние
(при непараллельности они различаются), отклонение угла, длина и доли перекрытия
для каждой линии, средняя линия на участке перекрытия в WCS. Отказы подсчитаны
по причинам в `rejected_pair_counts`: `separation_out_of_range`,
`no_projected_overlap`, `not_parallel`, `touching_or_crossing`, `different_planes`.

Линия может входить в несколько пар (например, средняя из трёх параллельных).
Такие линии перечислены в `ambiguous_handles`, у пар есть `ambiguous` и
`shared_line_handles`. Выбор «правильной» пары не делается. Ничего не
объединяется, не обрезается и не классифицируется; имён слоёв ядро не читает.
ID пары зависит от идентичности чертежа и состава двух линий.

Используются те же отбор и лимиты, что у диагностики LINE (`eligible_lines`):
100 линий, исключения видны в `excluded`, `coverage_complete=false` при
исключениях, неполном снимке или отфильтрованных handles/слоях.

## Архитектурный адаптер: `wall_segment_candidates`

`analyze_architectural_drawing(wall_thickness_range=[min, max])` применяет ядро
только к именованным wall/LINE кандидатам (те же правила отбора, что у
`wall_line_diagnostics`). Каждый участок содержит:

- `thickness_drawing_units` {min, max, mean} — геометрическое расстояние между гранями;
- `axis_wcs` — ось на участке, где нарисованы обе грани;
- исходные handles и `source_candidate_ids`;
- `physical_wall_verified=false`, `openings_checked=false`, `structural_role=unknown`.

Для неоднозначных граней добавляется issue `wall_segment_ambiguous_face`.
`physical_walls_assembled=false` и `structural_design_ready=false` остаются.

Не определяются: проёмы и перемычки, стыки и углы стен (участки разных
направлений не соединяются), многослойные конструкции (три грани дадут
неоднозначность), полилинии/MLINE/дуги, несущая функция. Толщина — это
расстояние между нарисованными линиями, а не подтверждённый тип стены.
Диапазон толщин задаёт пользователь по единицам DWG (например, [100, 400] мм).

## Полилинии как грани

С 2026-09-29 в поиске пар участвуют и прямые сегменты полилиний (LWPOLYLINE/
POLYLINE; для стен — кандидаты wall с формой open/closed_polyline). Общая функция
`split_polyline` (`polyline_parts.py`) раскладывает полилинию на отрезки с ключом
`<handle>#<индекс>`; в паре поле `sources` даёт исходный handle и `segment_index`
(`null` для обычного LINE). Сегменты одной полилинии сравниваются между собой,
поэтому стена, нарисованная одним замкнутым прямоугольником, даёт участок из его
длинных сторон. Дуги (bulge ≠ 0) не спрямляются: `arc_segment_not_supported` в
`excluded`, покрытие становится неполным; без bulge-данных —
`polyline_bulges_not_captured`.

С того же дня `wall_line_diagnostics`/`wall_networks` и общие `line_diagnostics`/
`line_networks` используют те же сегменты (общий выбор граней — `select_wall_faces`):
дубли, наложения, пересечения и зазоры находятся и между сегментами полилиний.
Соседние сегменты одной полилинии касаются по построению и в отношения не
выдаются (счётчик `same_polyline_adjacent_pairs`), но в группах контактов остаются
связанными. Поля `polyline_segments`/`same_polyline_adjacent_pairs` появляются
только при наличии сегментов, отчёты по одним LINE не меняются.

Сценарий живой проверки диагностики: к сценарию ниже добавить LINE D
(11400,2000)–(11500,2000) на A-WALL-TEST → overlap D–O#1, группы
[D, O#0, O#1], [I#0, I#1], [R#0..R#3], без `wall_line_diagnostics_incomplete`.

MLINE сейчас не поддерживается: scan не сохраняет её вершины и смещения стиля —
такие объекты остаются в `unclassified` (отдельный пункт backlog).

Сценарий живой проверки: на A-WALL-TEST прямоугольник (11000,2000)–(11200,2008)
и две открытые полилинии O (11300,2300)→(11300,2000)→(11800,2000),
I (11308,2300)→(11308,2008)→(11800,2008). `wall_thickness_range=[4,12]` →
3 участка (R#0/R#2, O#0/I#0, O#1/I#1) и corner в (11304,2004).

## Стыки участков: `junctions` / `pair_junctions`

Оси двух граней стены на углу обычно не доходят друг до друга на половину
толщины, поэтому стык ищется по пересечению бесконечных осей: точка может лежать
за концом оси не дальше допуска. Допуск по умолчанию — большая из двух толщин;
явно — `wall_junction_tolerance` (архитектурный отчёт) или `junction_tolerance`
(`analyze_geometry`, раздел `parallel_line_pairs.pair_junctions`).

| kind | Условие |
| --- | --- |
| `corner` | пересечение у концов обеих осей |
| `t_junction` | у конца одной оси и внутри другой |
| `crossing` | внутри обеих осей |
| `collinear_gap` | параллельны, на одной линии (смещение ≤ 10% допуска), разрыв концов ≤ допуска — возможный проём или разрыв чертежа, не подтверждается |
| `parallel_overlap` | параллельны с перекрытием и смещением ≤ допуска — обычно следствие неоднозначной грани |

Для стыка — ID участков, точка пересечения, угол, положение на каждой оси
(end/interior) и выход за конец. Участки не обрезаются и не объединяются,
контур здания и помещения не строятся. Лимит 500 осей; остальные в `skipped_axes`.

## Сценарий живой проверки стыков

Слой A-WALL-TEST, INSUNITS=in, толщина 8:

- V0 (11000,2000)–(11000,2300), V1 (11008,2008)–(11008,2300) — угол L в (11004,2004);
- T0 (11200,2008)–(11200,2300), T1 (11208,2008)–(11208,2300) — T-стык в (11204,2004);
- G0 (11540,2000)–(11700,2000), G1 (11540,2008)–(11700,2008) — продолжение после разрыва 40.

## Сценарий живой проверки

На новом слое A-WALL-TEST в чертеже с INSUNITS=in:

- A (0,0)–(200,0) и B (0,8)–(200,8) — пара, толщина 8, ось y=4;
- C (0,-6)–(200,-6) — вторая пара с A (толщина 6) → A неоднозначна;
- D (300,0)–(400,0) и E (350,8)–(450,8) — перекрытие 50, ось x 350–400;
- F (0,40)–(200,41) — не параллельна при допуске по умолчанию.

`analyze_architectural_drawing(wall_thickness_range=[4, 12])` → участки A–B,
A–C, D–E, issue по A; `analyze_geometry(layers=["A-WALL-TEST"],
parallel_separation_range=[4, 12])` → те же пары без архитектурных полей.
После анализа повторный scan не должен показывать изменений.
