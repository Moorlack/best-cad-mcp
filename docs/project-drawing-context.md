# Сверка карточки проекта с архитектурным отчётом

`analyze_architectural_drawing` принимает необязательный `project_id`.
Без него поведение прежнее: анализ кэша DWG без выбора карточки.
С ним читается актуальная ревизия карточки в текущем workspace. Ошибочный ID
или отсутствующая карточка возвращают ошибку, а не молчаливый анализ без проекта.

`report.project_context` содержит:

- project_id/revision — явно выбранный проект и прочитанную ревизию;
- project_units — значение, статус и источник из карточки;
- drawing_units/drawing_units_metadata — заявленные единицы из снимка DWG;
- declared_units_match — true/false или null, если сравнение невозможно;
- readiness — существующие списки отсутствующих/предполагаемых исходных данных;
- warnings — несовпадение, неподтверждённые/отсутствующие единицы проекта или
  отсутствие пригодных сведений о единицах DWG.

Совпадение строк `in` и `in` не доказывает масштаб геометрии. Статус confirmed
в карточке задан пользователем и не проверяется независимо. Даже при совпадении
geometry_scale_verified=false и engineering_design_ready=false.
Если единицы карточки assumed, совпадение может быть true, но предупреждение
project_units_unconfirmed сохраняется. Обычные ft и us_survey_ft не равны.

Это чтение в рамках одного запроса, не постоянная привязка DWG к проекту.
Карточка, её история, координаты и INSUNITS не изменяются; пересчёт размеров и
площадей не выполняется. Сравнивается кэш выбранного чертежа, а не другой активный
DWG: перед анализом нужен свежий scan_all_entities нужного документа.

## Проверка после установки

Обновление через прежний Repair / Extend, затем перезапуск клиента и AutoCAD.
Живая проверка установленной версии этого обновления ещё не выполнена.

1. Прочитать get_document_info и просканировать открытый тестовый DWG.
2. Создать отдельную синтетическую карточку с уникальным project_id, задав units
   как confirmed с источником «synthetic smoke test». Использовать известные
   единицы DWG (in/ft/mm/cm/m), expected_revision=0.
3. Вызвать analyze_architectural_drawing(project_id=этот_ID). Ожидать revision=1,
   declared_units_match=true, geometry_scale_verified=false. Если DWG unitless
   или неизвестен, не менять его автоматически: ожидать null и предупреждение.
4. Изменить units только тестовой карточки на другое значение с expected_revision=1.
   Ожидать revision=2, false и project_units_mismatch при известных единицах DWG.
5. Проверить вызов с несуществующим ID: явная ошибка. Вызов без project_id
   по-прежнему работает без project_context.
6. Проверить историю: анализ не создал дополнительных ревизий. Сравнить состояние
   DWG с исходным. Карточку оставить как тестовый артефакт, записать ID в backlog.

Для этого smoke-test изменение геометрии DWG не требуется. Инженерная проверка
фактического масштаба по контрольным размерам остаётся отдельным пунктом backlog.
