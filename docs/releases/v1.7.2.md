# v1.7.2 — DXF import and live CAD loop fixes

- Add `import_dxf(filepath, allow_modify=True)` using AutoCAD's native Import
  into a separate unsaved drawing. Reject DXF in `open_drawing` with an
  actionable instruction rather than using the DWG-only Open path.
- Repair malformed UTF-8 and unsupported header fields in the flange coupling
  fixture. Restore its cached diameter text from the existing 40 mm dimension.
- Regenerate display graphics before selection-set WMF export, addressing
  empty exports after import.
- Return a machine-readable handle from `move_entity` so CADPlan handle
  postconditions do not falsely fail and roll back a successful move.
- Update MCP tool-catalog coverage and add move-result regression tests.

Local validation: 430 tests and 473 subtests passed; Ruff passed.

Live exploratory verification on AutoCAD 2023 imported 91 entities, located the
leftmost exploded shaft through overlay E057, and moved handle 16E by -5 mm in X.
Rescan confirmed the target's four vertices moved as intended and the other
90 entities' scanned geometry and properties were unchanged; geometry validation
reported zero issues. Before/after rasters were visually inspected. Handles are
specific to that imported drawing and are not a reusable answer key.

This is a maintenance verification, not a controlled model benchmark. The run
included an import retry, a grounding ambiguity resolved through overlay and
entity inspection, and a verified rollback before the move-result fix. Semantic
ranking of large enclosing frames, cluttered overlays, and incomplete static
argument checks for some CADPlan operations remain follow-up work. Inspect the
named tool's argument schema; a dry-run alone does not prove call compatibility.
Existing frozen v1.7.1 baselines are unchanged; freeze a new baseline for model
comparisons using these fixes.
