# Проверка контуров

После свежего scan_all_entities архитектурный отчёт содержит boundary_checks
с исходными handles. У кандидата есть boundary_check. Проверяются одиночные
замкнутые горизонтальные полилинии с прямыми сегментами и известными WCS-координатами.

- valid_simple_polygon: простой контур в пределах заданного допуска;
  geometric_area_drawing_units_squared содержит геометрическую площадь.
- invalid: повторные/почти совпадающие вершины, вырожденная площадь,
  самопересечение/касание или наложение рёбер. Площадь null.
- not_verified: дуги, неполные сведения о кривизне, неподдерживаемая плоскость,
  координаты или превышение лимита. Площадь null.

Площадь выражена в квадратных единицах координат исходного чертежа. Даже при
INSUNITS=in это не подтверждение правильности физического масштаба. Отверстия,
вложенные контуры, назначение помещения/перекрытия и расчётные грузовые площади
не определяются: floor_area_verified=false, holes_checked=false.
Ошибочный контур может остаться кандидатом по имени слоя, но имеет явный
отрицательный результат проверки. structural_design_ready остаётся false.

Допуск 1e-9 относительно наибольшего XY-габарита после переноса/нормализации;
почти совпадающие или очень тонкие детали могут быть консервативно отклонены.
Лимит — 256 исходных вершин на контур, первые 100 замкнутых контуров по handle
в одном отчёте. Остальные явно помечаются not_verified. Отношения между
поддерживаемыми контурами теперь описаны в [boundary-relations.md](boundary-relations.md).
Отверстия как инженерные объекты и 3D-полилинии пока не проверяются.

Сканирование теперь сохраняет bulges_complete. Ошибка GetBulge не позволяет
признать сегменты прямыми и не создаёт приблизительный visual_path. Старый кэш
без этого признака требует повторного scan для проверки площади.

Обновление доставляется существующим Repair / Extend; новый CMD и зависимости
не нужны. Новый код проверен также на живом AutoCAD из рабочего checkout,
отдельно от установленного MCP.
