# Дуги открывания, контуры с дугами, цепочки стен, xref

Все четыре части — геометрические кандидаты для проверки человеком; ничего не подтверждается как дверь, помещение или стена.

## Дуги открывания (`opening_swings.py`)

- Источники дуг: одиночные `ARC` чертежа и дуги внутри определения блока двери (scan читает определение блока один раз на имя:
  до 200 объектов, до 16 дуг, `block_definition = {arcs, origin, entity_count, truncated}` в координатах блока; XRef/layout/вложенные блоки
  не обходятся, блок не взрывается и не копируется).
- Дуги блока переносятся в WCS по вставке (точка, поворот, равные по модулю масштабы, зеркало меняет направление; неравномерный масштаб
  и нормаль не +Z пропускаются).
- Для кандидата двери/окна в разрыве стены (`in_wall_gap`) `swing_arcs` содержит дуги, центр которых лежит у одного конца разрыва
  (допуск 15% ширины), радиус ≈ ширина (±20%), угол 30–180°: `hinge_end`, `hinge_distance`, `radius_to_opening_width_ratio`, `sweep_degrees`,
  `swing_side` (слева/справа от оси). `swing_status`: `swing_arc_candidate` / `none_found` / `not_evaluated_no_gap_width`.

## Контуры с дугами (`boundaries.check_boundary`)

Полилинии с `bulge` проверяются: самопересечения — по хордовой аппроксимации дуг (шаг 10°), площадь — точная (хордовый многоугольник плюс круговые
сегменты). Статус `valid_curved_contour` (не `valid_simple_polygon`), поэтому такие контуры не участвуют в отношениях вложенности и
попадают в `excluded_contour_handles`. Нормаль −Z и |bulge| > 1e6 не поддерживаются.

## Цепочки стен (`wall_runs.py`)

`wall_segment_candidates.runs`: сегменты с общей осью, связанные `collinear_gap` или `parallel_overlap`, объединяются в run-кандидат:
`span_length`, `drawn_length` (без двойного счёта наложений), `gap_length_total`, `gap_count`, `overlap_count`, диапазон толщины, `thickness_varies`.
Углы и T-стыки не объединяются; разрыв внутри run — не подтверждённый проём.

## Xref и область

Ссылки на xref-блоки получают issue `xref_reference_not_expanded` (содержимое не читается). В ограничениях отчёта: сканируется только
model space, листы/layouts и этажи не определяются.

## Имена слоёв и блоков (`name_profiles.py`)

До этого имена разбирались только латиницей `[a-z]+`: слои вроде «АР_Стены», «Двери», «Окна» не распознавались вообще. Теперь токены —
последовательности букв любого алфавита (разделители `_`, `-`, цифры, CamelCase; «ё»→«е»). Встроенные словари: английский, русский,
украинский, русская транслитерация, немецкий (стена/стены/стен…, дверь/двери…, окно/окна…, проём, колонна, плита/перекрытие, помещение, ось/сетка, стіна, вікно…).
Совпадение — целыми словами (WALL не ловит WALLPAPER). Параметр `name_aliases={wall|door|window|opening|grid|column|slab_boundary|room_boundary: [слова]}`
у `analyze_architectural_drawing` добавляет слова проекта (до 64 слов, одно слово из букв до 40 символов). Совпадение имени остаётся подсказкой.

## Замкнутые контуры стен (`room_loops.py`, `wall_segment_candidates.room_loops`)

Оси парных граней соединяются в точках стыков (угол, T, пересечение) и, при `wall_opening_max_width`, через разрывы проёмов; ограниченные грани плоского
графа — кандидаты замкнутых областей. Площадь считается по ОСЯМ стен (толщина не вычитается), `closed_through_opening_gap` помечает контуры, замкнутые через проём,
`room_confirmed=false` всегда. Висячие стены отбрасываются; оси без стыков в допуске контур не образуют.

## Масштабируемость на реальные планы (`spatial_pairs.py`)

До этого анализ линий резал входные данные: `MAX_LINES = 100` (остальные грани стен молча попадали в `line_limit_exceeded`), `MAX_AXES = 500`,
`MAX_LOOP_AXES = 500`, 100 проверяемых контуров; все парные проверки были квадратичными. Реальный план — тысячи граней. Теперь лимиты 5000 линий/осей и
500 контуров, а при более чем 150 элементах пары отбираются по пересечению рамок с запасом (шаг сетки — медианный размер, слишком большие рамки сравниваются со всеми):
для параллельных пар запас = максимальная толщина, для стыков и разрывов — допуск/ширина, для диагностики линий — допуск поиска зазоров (такие пары заведомо
«disjoint» и считаются проверенными без вызова теста). Малые входы считаются как раньше, результаты и порядок пар те же; в `rejected_pair_counts` появляется `far_apart_pruned`.
Замер: 3000 граней (1500 сегментов) — отчёт строится за ~0.4 с.

## Проверка масштаба по размерам (`dimension_scale.py`, `dimension_scale_check`)

scan читает у линейных размеров (`RotatedDimension`, `AlignedDimension`) значение `Measurement`, две точки выносных линий, поворот, `TextOverride` и `LinearScaleFactor`.
Отчёт сравнивает значение с расстоянием между точками вдоль направления размера (допуск 1%); размеры с подменённым текстом или коэффициентом ≠ 1 пропускаются.
`dimension_scale_consistent` / `dimension_scale_mismatch` — только согласованность геометрии с её размерами; единицы и реальный масштаб остаются заявленными (`units_verified=false`).
