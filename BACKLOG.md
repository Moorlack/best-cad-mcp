# AutoCAD MCP — backlog инженерного процесса

Обновлено: 2026-09-21. Этот файл фиксирует согласованный объём работы и фактическую готовность. При продолжении работы сверяться с ним; после реализации обновлять статус, доказательства проверки и оставшиеся ограничения. Наличие пункта в backlog не означает разрешения автоматически выполнять весь список.

## Цель

Claude получает архитектурный DWG, помогает восстановить устройство здания, сформировать расчётную модель и нагрузки, предложить несущие элементы и выпустить проверяемый отчёт и конструктивную схему. Расчёты должны быть воспроизводимыми, решения — связанными с исходной геометрией и применимыми нормативными источниками. Результаты для строительного применения проверяет квалифицированный инженер.

Источник кода: [Moorlack/best-cad-mcp](https://github.com/Moorlack/best-cad-mcp), основная ветка **master**. Не путать с Revit fork `Moorlack/aec-model-bridge`.

Критерий готовности: одинаковые входные данные дают воспроизводимый результат; контрольные расчёты совпадают в согласованных допусках, формулы и ограничения видны в отчёте. Наличие Python само по себе не доказывает корректность инженерной модели.

Расчётные модули можно предоставлять через тот же MCP, без обязательной настройки нескольких серверов пользователем.

## Недостающие входные материалы и ближайшие шаги

Инженер пока не предоставил архитектурный DWG, эталонный расчёт и согласованную нормативную базу. Это ограничивает проверку реальных инженерных результатов, но не мешает подготовке схем данных и синтетических тестов.

1. Запись/чтение карточки из Claude подтверждены smoke-test; вызов архитектурного анализа остаётся отдельной незадокументированной проверкой. Подключение больше не является блокером.
2. Выбрать следующий ограниченный пункт backlog по задаче пользователя; не объявлять весь разбор DWG завершённым по наличию первого инструмента. Карточка проекта теперь имеет проверенную базовую реализацию.
3. После получения материалов согласовать пилотный сценарий и критерии приёмки с инженером.

При завершении пункта записывать коммит/файлы, выполненную проверку и её пределы. Отдельно отмечать «код готов», «установлен», «доступен клиенту» и «проверен инженером» — это разные состояния.
